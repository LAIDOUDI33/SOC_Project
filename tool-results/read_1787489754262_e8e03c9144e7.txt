    68→## Hypothesis-Based Hunting Methodology
    69→
    70→### What is Threat Hunting?
    71→
    72→Threat hunting is the proactive search for threats that have evaded existing security controls. Unlike alert-driven incident response, hunting assumes the adversary may already be inside.
    73→
    74→```mermaid
    75→flowchart LR
    76→    subgraph Reactive["Reactive (Traditional)"]
    77→        A1[Alert Fires] --> A2[Investigate]
    78→        A2 --> A3[Respond]
    79→        A3 --> A4[Close]
    80→    end
    81→    
    82→    subgraph Proactive["Proactive (Hunting)"]
    83→        B1[Form Hypothesis] --> B2[Search for Evidence]
    84→        B2 --> B3{Found?}
    85→        B3 -->|Yes| B4[Investigate/Respond]
    86→        B3 -->|No| B5[Refine Hypothesis]
    87→        B5 --> B2
    88→        B4 --> B6[Create Detection]
    89→        B6 --> B1
    90→    end
    91→    
    92→    style Reactive fill:#ffcdd2
    93→    style Proactive fill:#c8e6c9
    94→```

    96→### The Hunting Lifecycle
    97→
    98→#### Phase 1: Hypothesis Development
    99→
   100→A hypothesis is a testable statement about potential adversary activity in your environment.
   101→
   102→**Hypothesis Formula:**
   103→```
   104→I believe that [THREAT ACTOR / TECHNIQUE] 
   105→may be present in our environment, 
   106→evidenced by [OBSERVABLE BEHAVIOR], 
   107→which I can detect by querying [DATA SOURCE] for [SPECIFIC INDICATORS].
   108→```
   109→
   110→**Example Hypotheses:**
   111→
   112→| # | Hypothesis | Data Source | Technique |
   113→|---|-----------|-------------|-----------|
   114→| H1 | An attacker with initial access via phishing is attempting credential dumping using comsvcs.dll on domain-joined workstations | GRR EDR + Wazuh | T1003.003 (OS Credential Dumping) |
   115→| H2 | APT group targeting telecom is using DNS tunneling for C2 communications, utilizing newly registered .tk domains | Zeek DNS logs + Suricata | T1048.003 (Exfiltration Over Alternative Protocol) |
   116→| H3 | Insider threat is exfiltrating subscriber data via personal email using base64 encoding in attachments | Proxy logs + DLP alerts | T1567.002 (Exfiltration to Web Service) |
   117→
   118→**Hypothesis Quality Criteria:**
   119→
   120→| Criterion | Good Example | Poor Example |
   121→|-----------|--------------|--------------|
   122→| **Specific** | "Attacker using Mimikatz via PowerShell on servers" | "Someone might be doing something bad" |
   123→| **Testable** | Can be verified with available data | Requires unavailable telemetry |
   124→| **Actionable** | Finding leads to response | Finding has no clear action |
   125→| **Relevant** | Based on current threat intel or risk | Random exploration without context |
   126→
   127→#### Phase 2: Data Collection & Query Development
   128→
   129→Translate hypothesis into executable queries:
   130→
   131→```python
   132→# Hypothesis H1 Implementation Example
   133→# Hunting for credential dumping via comsvcs.dll
   134→
   135→class CredentialDumpingHunt:
   136→    """
   137→    Hypothesis: Attackers are using comsvcs.dll MiniDump 
   138→    technique for credential extraction.
   139→    
   140→    MITRE ATT&CK: T1003.003 - OS Credential Dumping:
   141→    Operating System utilities that dump credentials.
   142→    """
   143→    
   144→    def __init__(self):
   145→        self.queries = {
   146→            'wazuh': """
   147→                SELECT * FROM alerts 
   148→                WHERE rule.id IN (
   149→                    '550', '554',  # Process creation rules
   150→                    '553'          # New file creation
   151→                )
   152→                AND full_log LIKE '%comsvcs%'
   153→                AND timestamp > now() - interval '7 days'
   154→            """,
   155→            
   156→            'grr_flows': [
   157→                {'name': 'FileFinder', 
   158→                 'params': {'path_regex': '.*dump.*\\.dmp', 'path': '/tmp,/Users/*/Downloads'}},
   159→                {'name': 'YaraScan',
   160→                 'params': {'rules_path': '/opt/yara/credential_dump.yara'}}
   161→            ],
   162→            
   163→            'zeek': """
   164→                SELECT * FROM files 
   165→                WHERE filename LIKE '%dump%' 
   166→                  AND mime_type = 'application/x-dmp'
   167→                  AND ts > now() - interval '7 days'
   168→            """
   169→        }
   170→        
   171→    def execute_hunt(self):
   172→        """Execute all queries and correlate results"""
   173→        results = {}
   174→        
   175→        # Execute Wazuh query
   176→        results['wazuh_alerts'] = self.query_wazuh(self.queries['wazuh'])
   177→        
   178→        # Execute GRR flows on target systems
   179→        results['grr_artifacts'] = self.execute_grr_flows(self.queries['grr_flows'])
   180→        
   181→        # Query Zeek for suspicious file transfers
   182→        results['network_files'] = self.query_zeek(self.queries['zeek'])
   183→        
   184→        return self.correlate(results)
   185→```
   186→
   187→#### Phase 3: Analysis & Pattern Recognition
   188→
   189→Look for patterns that confirm or refute your hypothesis:
   190→
   191→**Pattern Types to Identify:**
   192→
   193→| Pattern Type | Description | Example |
   194→|-------------|-------------|---------|
   195→| **Temporal** | Events clustered in time | Multiple credential accesses at 3 AM |
   196→| **Spatial** | Events from same location/source | Same source IP accessing multiple hosts |
   197→| **Behavioral** | Similar actions across entities | Same unusual command on multiple systems |
   198→| **Anomalous** | Deviation from baseline | User suddenly accessing new systems |
   199→| **Correlated** | Related events across sources | Network connection + file creation + process execution |
   200→
   201→#### Phase 4: Response & Detection Enhancement
   202→
   203→If hypothesis confirmed:
   204→
   205→1. **Immediate Response**
   206→   - Contain affected systems
   207→   - Preserve evidence
   208→   - Initiate incident if warranted
   209→
   210→2. **Detection Creation**
   211→   - Convert hunt query to detection rule
   212→   - Add to SIEM/correlation engine
   213→   - Document for team awareness
   214→
   215→3. **Knowledge Sharing**
   216→   - Brief stakeholders
   217→   - Update threat model
   218→   - Improve defenses

   380→## Advanced Query Techniques
   381→
   382→### SQL Advanced Patterns for PostgreSQL
   383→
   384→The SOC platform uses PostgreSQL as its primary database. Master these patterns:
   385→
   386→#### Time-Series Analysis
   387→
   388→```sql
   389→-- Detect anomalies in event volume over time
   390→WITH hourly_counts AS (
   391→    SELECT 
   392→        DATE_TRUNC('hour', created_at) AS hour,
   393→        COUNT(*) AS event_count,
   394→        source_type
   395→    FROM events
   396→    WHERE created_at >= NOW() - INTERVAL '7 days'
   397→    GROUP BY hour, source_type
   398→),
   399→stats AS (
   400→    SELECT 
   401→        source_type,
   402→        AVG(event_count) AS avg_count,
   403→        STDDEV(event_count) AS std_count,
   404→        PERCENTILE_CONT(0.95) WITHIN GROUP (ORDER BY event_count) AS p95_count
   405→    FROM hourly_counts
   406→    GROUP BY source_type
   407→)
   408→SELECT 
   409→    h.hour,
   410→    h.source_type,
   411→    h.event_count,
   412→    s.avg_count,
   413→    s.p95_count,
   414→    CASE 
   415→        WHEN h.event_count > s.p95_count * 2 THEN 'ANOMALOUS_HIGH'
   416→        WHEN h.event_count < s.avg_count * 0.1 THEN 'ANOMALOUS_LOW'
   417→        ELSE 'NORMAL'
   418→    END AS anomaly_flag
   419→FROM hourly_counts h
   420→JOIN stats s ON h.source_type = s.source_type
   421→WHERE h.event_count > s.p95_count * 2 OR h.event_count < s.avg_count * 0.1
   422→ORDER BY h.hour DESC;
   423→```
   424→
   425→#### Graph/Relationship Queries
   426→
   427→```sql
   428→-- Find users who accessed similar sets of sensitive tables
   429→-- May indicate coordinated activity or shared compromised account
   430→
   431→WITH user_table_access AS (
   432→    SELECT DISTINCT
   433→        username,
   434→        table_name,
   435→        DATE(access_time) AS access_date
   436→    FROM audit_log
   437→    WHERE table_name IN ('subscribers', 'imsi_mapping', 'cdr_archive')
   438→      AND access_time >= NOW() - INTERVAL '30 days'
   439→),
   440→user_access_patterns AS (
   441→    SELECT 
   442→        a.username AS user_a,
   443→        b.username AS user_b,
   444→        COUNT(*) AS common_tables,
   445→        array_agg(DISTINCT a.table_name) AS shared_tables
   446→    FROM user_table_access a
   447→    JOIN user_table_access b 
   448→        ON a.table_name = b.table_name 
   449→        AND a.access_date = b.access_date
   450→        AND a.username < b.username
   451→    GROUP BY a.username, b.username
   452→    HAVING COUNT(*) >= 3  -- Accessed 3+ same sensitive tables
   453→)
   454→SELECT *
   455→FROM user_access_patterns
   456→ORDER BY common_tables DESC;
   457→```

   459→#### Sessionization Analysis
   460→
   461→```sql
   462→-- Analyze authentication sessions for impossible travel or sharing
   463→
   464→WITH auth_events AS (
   465→    SELECT 
   466→        username,
   467→        client_ip,
   468→        geoip_country(client_ip) AS country,
   469→        geoip_city(client_ip) AS city,
   470→        event_time,
   471→        LAG(event_time) OVER (PARTITION BY username ORDER BY event_time) AS prev_time,
   472→        LAG(client_ip) OVER (PARTITION BY username ORDER BY event_time) AS prev_ip,
   473→        ROW_NUMBER() OVER (PARTITION BY username ORDER BY event_time) AS rn
   474→    FROM authentication_log
   475→    WHERE success = true
   476→      AND event_time >= NOW() - INTERVAL '24 hours'
   477→),
   478→session_analysis AS (
   479→    SELECT *,
   480→        EXTRACT(EPOCH FROM (event_time - prev_time)) / 3600 AS hours_since_prev,
   481→        CASE 
   482→            WHEN country != geoip_country(prev_ip) THEN 'COUNTRY_CHANGE'
   483→            WHEN city != geoip_city(prev_ip) THEN 'CITY_CHANGE'
   484→            ELSE 'SAME_LOCATION'
   485→        END AS location_change
   486→    FROM auth_events
   487→    WHERE rn > 1
   488→)
   489→SELECT *
   490→FROM session_analysis
   491→WHERE 
   492→    -- Impossible travel: different country within 4 hours
   493→    (location_change = 'COUNTRY_CHANGE' AND hours_since_prev < 4)
   494→    OR
   495→    -- Suspicious rapid location change
   496→    (location_change = 'CITY_CHANGE' AND hours_since_prev < 1)
   497→ORDER BY event_time DESC;
   498→```

   500→### Zeek/Zq Advanced Queries
   501→
   502→Zq is the modern query language for Zeek logs:
   503→
   504→```zq
   505→# Complex network behavior detection
   506→
   507→# Long-lived connections that transferred significant data
   508→filter(
   509→    duration > 10min && bytes > 10MB,
   510→    read_conn("conn.log")
   511→)
   512→
   513→# DNS queries to domains with high entropy (possible DGA)
   514→let entropy(s: string) = count(for c in set(s) -> {c}) / len(s)
   515→filter(
   516→    entropy(query) > 3.5 && !query endsWith(djezzy.dz) && !query endsWith(.google.com),
   517→    read_dns("dns.log")
   518→)
   519→
   520→# Potential Kerberos attacks: unusual ticket types
   521→filter(
   522→    service == "kerberos" && proto == "udp" && bytes > 2000,
   523→    read_conn("conn.log")
   524→)
   525→
   526→# Beaconing detection: regular intervals in connections
   527→let intervals = cut(id.orig_h, id.resp_h, id.resp_p, 
   528→                    map(each(cut(ts, id.resp_h)), 
   529→                        {ts, next_ts=next(ts)}))
   530→filter(
   531→    abs(next_ts - ts) < stddev(next_ts - ts) * 0.1,
   532→    intervals
   533→)
   534→```

   541→// Rule: Telecom-specific credential stealer detection

   544→rule Telecom_Credential_Stealer {

   549→        version = "1.0"
   550→        mitre_tactic = "Credential Access"
   551→        mitre_technique = "T1003"
   552→        severity = "high"
   553→
   554→    strings:
   555→        // Strings related to telecom databases
   556→        $db_subscriber = "subscriber" nocase wide ascii
   557→        $db_cdr = "call_detail" nocase wide ascii
   558→        $db_imsi = "imsi" nocase wide ascii
   559→        
   560→        // Credential-related API calls
   561→        $cred_api1 = "CredReadDomainCredentials" ascii wide
   562→        $cred_api2 = "CryptUnprotectData" ascii wide
   563→        $cred_api3 = "WlanGetProfile" ascii wide
   564→        
   565→        // Network indicators of C2
   566→        $c2_path1 = "/api/callback" ascii
   567→        $c2_path2 = "/exfil" ascii
   568→        $user_agent = "TelecomClient/" ascii wide
   569→        
   570→        // Suspicious encryption patterns
   571→        $enc_pattern = { 89 50 4E 47 }  // PNG header (steganography?)
   572→        $base64_pattern = /[A-Za-z0-9+/]{40,}={0,2}/
   573→
   574→    condition:
   575→        // Main condition: credential stealing behavior
   576→        any of ($cred_*) 
   577→        and (
   578→            // With telecom targeting
   579→            any of ($db_*)
   580→            or
   581→            // Or C2 communication
   582→            2 of ($c2_*)
   583→        )
   584→        and filesize < 5MB
   585→}

   588→// Note: This would typically run on extracted strings from network captures
   589→
   590→rule DNS_Tunneling_Tool {
   591→    meta:
   592→        description = "Detects known DNS tunneling tool artifacts"
   593→        severity = "critical"
   594→    
   595→    strings:
   596→        // iodine/dns2tcp signatures
   597→        $iodine_str1 = "iodine" nocase ascii
   598→        $iodine_str2 = "-f" ascii // iodine frequent flag
   599→        $dnscat_str = "dnscat" nocase ascii
   600→        $tun_str1 = ".tunnel" nocase ascii
   601→        $tun_str2 = ".dns" nocase wide
   602→        
   603→        // High entropy subdomain pattern (DGA-like)
   604→        $high_entropy_domain = /[a-z]{20,}\.(tk|ml|ga|cf|gq)\./ ascii nocase
   605→
   606→    condition:
   607→        any of ($*) and filesize < 500KB
   608→}

   728→# intelligence_hunter.py
   729→# Framework for intelligence-led threat hunting

   731→import requests
   732→from datetime import datetime, timedelta
   733→from typing import List, Dict, Any
   734→
   735→class IntelligenceHunter:
   736→    """Integrate threat intelligence into hunting operations"""
   737→    
   738→    def __init__(self, misp_url, misp_key, opencti_url, opencti_key):
   739→        self.misp_url = misp_url
   740→        self.misp_key = misp_key
   741→        self.opencti_url = opencti_url
   742→        self.opencti_key = opencti_key
   743→        
   744→    def get_recent_threat_actors(self, days: int = 7) -> List[Dict]:
   745→        """Get active threat actors from OpenCTI"""
   746→        # Query for intrusion sets with recent activity
   747→        query = '''
   748→        query {
   749→            intrusionSets(first: 20) {
   750→                edges {
   751→                    node {
   752→                        id
   753→                        name
   754→                        aliases
   755→                        description
   756→                        objectMarking {
   757→                            edges {
   758→                                node {
   759→                                    definition
   760→                                    x_opencti_color
   761→                                }
   762→                            }
   763→                        }
   764→                        firstSeen
   765→                        lastSeen
   766→                        objectLabel {
   767→                            edges {
   768→                                node {
   769→                                    value
   770→                                }
   771→                            }
   772→                        }
   773→                    }
   774→                }
   775→            }
   776→        }
   777→        '''
   778→        result = self._opencti_query(query)
   779→        return self._parse_intrusion_sets(result)
   780→    
   781→    def get_actor_ttps(self, actor_id: str) -> List[str]:
   782→        """Get MITRE ATT&CK techniques used by threat actor"""
   783→        query = f'''
   784→        {{
   785→            intrusionSet(id: "{actor_id}") {{
   786→                objectIncludes {{
   787→                    edges {{
   788→                        node {{
   789→                            ... on AttackPattern {{
   790→                                name
   791→                                x_mitre_id
   792→                                killChainPhases {{
   793→                                    phase_name
   794→                                }}
   795→                            }}
   796→                        }}
   797→                    }}
   798→                }}
   799→            }}
   800→        }}
   801→        '''
   802→        result = self._opencti_query(query)
   803→        return self._parse_attack_patterns(result)
   804→    
   805→    def extract_actor_iocs(self, actor_id: str) -> Dict[str, List]:
   806→        """Extract all IOCs associated with threat actor"""
   807→        iocs = {'ips': [], 'domains': [], 'hashes': [], 'urls': []}
   808→        
   809→        # Get stix bundles from MISP for this actor
   810→        misp_search = {
   811→            'type': ['ip-dst', 'domain', 'md5', 'sha256', 'url'],
   812→            'tag': f'threat-actor:{actor_id}',
   813→            'publish_timestamp': (datetime.now() - timedelta(days=90)).strftime('%Y-%m-%d')
   814→        }
   815→        
   816→        resp = requests.post(
   817→            f'{self.misp_url}/attributes/restSearch',
   818→            headers={'Authorization': self.misp_key},
   819→            json=misp_search
   820→        )
   821→        
   822→        for attr in resp.json().get('Attribute', []):
   823→            type_map = {
   824→                'ip-dst': 'ips',
   825→                'domain': 'domains',
   826→                'md5': 'hashes',
   827→                'sha256': 'hashes',
   828→                'urls': 'urls'
   829→            }
   830→            target = type_map.get(attr.get('type'))
   831→            if target:
   832→                iocs[target].append(attr.get('value'))
   833→        
   834→        return iocs
   835→    
   836→    def generate_hunt_queries(self, iocs: Dict[str, List]) -> List[str]:
   837→        """Generate platform-specific queries from IOCs"""
   838→        queries = []
   839→        
   840→        # SQL queries for internal database
   841→        if iocs['ips']:
   842→            ip_list = "', '".join(iocs['ips'][:100])  # Limit for performance
   843→            queries.append(f"""
   844→                SELECT * FROM network_connections 
   845→                WHERE remote_ip IN ('{ip_list}')
   846→                AND connection_time > NOW() - INTERVAL '30 days'
   847→                ORDER BY connection_time DESC
   848→            """)
   849→        
   850→        if iocs['domains']:
   851→            domain_list = "', '".join(iocs['domains'][:50])
   852→            queries.append(f"""
   853→                SELECT * FROM dns_queries 
   854→                WHERE query_name ~* '\\.({domain_list.replace(".", "\\.")})$'
   855→                AND query_time > NOW() - INTERVAL '30 days'
   856→            """)
   857→        
   858→        # Wazuh query format
   859→        if iocs['hashes']:
   860→            for hash_val in iocs['hashes']:
   861→                queries.append(f'search={hash_val}&rule.level=7+')
   862→        
   863→        return queries
   864→    
   865→    def _opencti_query(self, query: str) -> Dict:

   870→            json={'query': query}
   871→        )
   872→        return resp.json()

   935→### Case Study 1: SS7/Diameter Signaling Attack
   936→
   937→**Background:**
   938→In 2024, a major Algerian telecommunications provider experienced a sophisticated attack leveraging SS7 protocol vulnerabilities to track high-value targets and intercept SMS-based 2FA codes.
   939→
   940→**Attack Timeline:**
   941→
   942→| Phase | Date | Activity | Detection Method |
   943→|-------|------|----------|------------------|
   944→| Reconnaissance | Jan 15 | Subscriber enumeration via signaling probes | Unusual signaling volumes |
   945→| Initial Access | Jan 22 | SS7 routing manipulation | Diameter monitoring |
   946→| Action | Jan 25-Feb 10 | Location tracking of 47 targets | Location query anomalies |
   947→| Exfiltration | Feb 8-12 | Intercepted 2FA codes forwarded | SMS delivery failures reported |
   948→| Discovery | Feb 14 | Security team alerted to complaints | Customer reports + anomaly detection |
   949→
   950→**Lessons Learned:**
   951→1. Signaling layer monitoring is essential for telecom SOC
   952→2. Cross-reference customer complaints with technical data
   953→3. Implement roaming partner security verification
   954→4. Deploy signaling firewall with strict rules
   955→
   956→**Detection Rules Developed:**
   957→```yaml
   958→# Rule: Unusual SS7 location queries
   959→title: High Volume Location Requests for Single Subscriber
   960→description: Detect potential tracking via excessive location queries
   961→condition: location_requests_per_subscriber > 50 AND time_window < 1 hour
   962→severity: critical
   963→
   964→# Rule: SMS Interception Indicators
   965→title: SMS Delivery Failure After Successful Routing
   966→description: Possible interception - message routed but not delivered
   967→condition: sms_routed_success AND delivery_failed AND destination_in_target_set
   968→severity: critical
   969→```

   971→### Case Study 2: SIM Swapping Fraud Ring
   972→
   973→**Background:**
   974→Organized fraud ring exploited social engineering and insider assistance to perform unauthorized SIM swaps, enabling account takeovers of cryptocurrency and banking accounts.
   975→
   976→**Attack Pattern:**
   977→
   978→```mermaid
   979→flowchart TD
   980→    A[Target Selection] --> B[Information Gathering]
   981→    B --> C[Social Engineering - Call Center]
   982→    C --> D{Success?}
   983→    D -->|No| E[Insider Recruitment Attempt]
   984→    D -->|Yes| F[SIM Swap Request]
   985→    E --> F
   986→    F --> G[Fraudulent Port/Swap]
   987→    G --> H[Account Takeover]
   988→    H --> I[Financial Theft]
   989→```
   990→
   991→**Indicators of Compromise (IOCs):**
   992→
   993→| Category | Indicator |
   994→|----------|-----------|
   995→| **Behavioral** | Multiple SIM swap requests for same subscriber |
   996→| **Behavioral** | Call center calls from same number about different accounts |
   997→| **Technical** | Port-in requests followed immediately by 2FA usage |
   998→| **Technical** | Device change + immediate high-value transaction |
   999→| **Insider** | Employee accessing records outside normal territory |
  1000→
  1001→**Hunting Queries:**
  1002→```sql
  1003→-- Find potential SIM swap fraud patterns
  1004→WITH port_events AS (
  1005→    SELECT 
  1006→        msisdn,
  1007→        port_type,  -- port-in, port-out, swap
  1008→        request_time,
  1009→        requesting_employee_id,
  1010→        reason_code,
  1011→        LAG(request_time) OVER (PARTITION BY msisdn ORDER BY request_time) AS prev_port
  1012→    FROM sim_port_log
  1013→    WHERE request_time >= NOW() - INTERVAL '30 days'
  1014→),
  1015→suspicious_patterns AS (
  1016→    SELECT *
  1017→    FROM port_events
  1018→    WHERE port_type = 'swap'
  1019→      AND EXISTS (
  1020→          SELECT 1 FROM port_events p2 
  1021→          WHERE p2.msisdn = port_events.msisdn 
  1022→            AND p2.port_type = 'swap'
  1023→            AND p2.request_time > port_events.request_time - INTERVAL '7 days'
  1024→            AND p2.request_id != port_events.request_id
  1025→      )
  1026→)
  1027→SELECT * 
  1028→FROM suspicious_patterns
  1029→ORDER BY request_time DESC;
  1030→```

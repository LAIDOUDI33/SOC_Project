## API Overview

### Base URL

| Environment | Base URL |
|------------|-----------|
| **Production** | `https://api.soc.djezzy.local` |
| **Staging** | `https://staging-api.soc.djezzy.local` |
| **Development** | `https://dev-api.soc.djezzy.local` |

### API Versioning

The API uses URL path versioning:

```
Current Version: /api/v1
Deprecated: None
```

All requests should use the v1 endpoint. Breaking changes will be released under `/api/v2`.

### Content Types

| Content-Type | Usage |
|--------------|-------|
| `application/json` | Standard for all request/response bodies |
| `multipart/form-data` | File uploads (evidence, reports) |
| `text/event-stream` | Server-Sent Events (real-time streams) |

### Response Format

All responses follow a consistent envelope format:

```typescript
// Standard Success Response
interface ApiResponse<T> {
  success: true;
  data: T;
  meta?: {
    page?: number;
    per_page?: number;
    total?: number;
    total_pages?: number;
    timestamp: string;
    request_id: string;
  };
}

// Error Response
interface ApiError {
  success: false;
  error: {
    code: string;
    message: string;
    details?: Record<string, unknown>;
    documentation_url?: string;
  };
  meta: {
    timestamp: string;
    request_id: string;
  };
}
```

## Authentication & Authorization

### Authentication Methods

#### Method 1: Bearer Token (JWT)

```http
Authorization: Bearer eyJhbGciOiJIUzI1NiIsInR5cCI6IkpXVCJ9...
```

#### Method 2: Session Cookie

For browser-based applications, session cookies are set after login:

```http
Cookie: soc_session=abc123xyz; Path=/; HttpOnly; Secure; SameSite=Strict
```

### Obtaining Authentication Tokens

#### POST /api/auth/login

Authenticate with credentials to receive JWT token.

**Request:**

```json
{
  "username": "analyst@djezzy.dz",
  "password": "secure_password_123"
}
```

**Response (200 OK):**

```json
{
  "success": true,
  "data": {
    "token": "eyJhbGciOiJIUzI1NiIsInR5cCI6IkpXVCJ9...",
    "refresh_token": "eyJhbGciOiJIUzI1NiIsInR5cCI6IkpXVCJ9...",
    "expires_in": 3600,
    "user": {
      "id": "usr_abc123",
      "username": "analyst",
      "display_name": "Ahmed Benali",
      "role": "analyst",
      "permissions": ["alerts:read", "incidents:read", "incidents:create"]
    }
  },
  "meta": {
    "timestamp": "2025-01-15T10:30:00Z",
    "request_id": "req_abc123"
  }
}
```

#### POST /api/auth/refresh

Refresh an expired access token using a refresh token.

**Request Headers:**

```http
Authorization: Bearer <refresh_token>
```

**Response (200 OK):**

```json
{
  "success": true,
  "data": {
    "token": "eyJhbGciOiJIUzI1NiIsInR5cCI6IkpXVCJ9...",
    "expires_in": 3600
  }
}
```

#### POST /api/auth/logout

Invalidate current session/token.

**Response (200 OK):**

```json
{
  "success": true,
  "data": {
    "message": "Successfully logged out"
  }
}
```

### Token Validation Endpoint

#### GET /api/auth/validate

Validate if a token is still valid without refreshing.

**Request Headers:**

```http
Authorization: Bearer <access_token>
```

**Response (200 OK):**

```json
{
  "success": true,
  "data": {
    "valid": true,
    "expires_in": 2847,
    "user_id": "usr_abc123"
  }
}
```

**Response (401 Unauthorized):**

```json
{
  "success": false,
  "error": {
    "code": "TOKEN_EXPIRED",
    "message": "Token has expired. Please refresh or re-authenticate."
  }
}
```

## Alerts API

The Alerts API provides access to security alerts generated by the SOC platform.

### List All Alerts

#### GET /api/alerts

Retrieve paginated list of alerts with optional filtering.

**Query Parameters:**

| Parameter | Type | Default | Description |
|-----------|------|---------|-------------|
| `page` | integer | 1 | Page number |
| `per_page` | integer | 20 | Items per page (max: 100) |
| `severity` | string | - | Filter by severity: `critical`, `high`, `medium`, `low` |
| `status` | string | - | Filter by status: `new`, `acknowledged`, `in_progress`, `closed`, `false_positive` |
| `source` | string | - | Filter by source system: `wazuh`, `suricata`, `zeek`, `misp`, `fraud` |
| `type` | string | - | Alert type/category |
| `assigned_to` | string | - | Filter by assigned analyst ID |
| `date_from` | datetime | - | Start date filter (ISO 8601) |
| `date_to` | datetime | - | End date filter (ISO 8601) |
| `sort` | string | `-created_at` | Sort field (prefix with `-` for descending) |

curl -X GET "https://api.soc.djezzy.local/api/v1/alerts?severity=critical&status=new&per_page=50" \

### Update Alert Status

#### PATCH /api/alerts/:id/status

Update the status of an alert.

**Request Body:**

```json
{
  "status": "in_progress",
  "comment": "Escalating to Tier 2 for deeper investigation due to critical assets involved."
}
```

**Allowed Status Transitions:**

| Current Status | Allowed Next Statuses |
|----------------|----------------------|
| `new` | `acknowledged`, `in_progress`, `closed`, `false_positive` |
| `acknowledged` | `in_progress`, `closed`, `false_positive` |
| `in_progress` | `closed`, `false_positive`, `escalated` |
| `false_positive` | `closed` |
| `closed` | `reopened` (special case) |

**Response (200 OK):**

```json
{
  "success": true,
  "data": {
    "id": "alert_abc123",
    "status": "in_progress",
    "updated_at": "2025-01-15T11:00:00Z",
    "status_history": [
      {
        "from": "acknowledged",
        "to": "in_progress",
        "at": "2025-01-15T11:00:00Z",
        "by": "usr_analyst01",
        "comment": "Escalating to Tier 2..."
      }
    ]
  }
}
```

## Error Codes

### Standard Error Format

All errors follow this structure:

```json
{
  "success": false,
  "error": {
    "code": "ERROR_CODE",
    "message": "Human-readable error message",
    "details": {},
    "documentation_url": "https://docs.soc.djezzy.local/errors/ERROR_CODE"
  },
  "meta": {
    "timestamp": "2025-01-15T10:30:00Z",
    "request_id": "req_abc123"
  }
}
```

### Error Code Reference

| HTTP Status | Error Code | Description | Resolution |
|-------------|-----------|-------------|------------|
| **400** | `VALIDATION_ERROR` | Request validation failed | Check request body against schema |
| **400** | `INVALID_PARAMETER` | Parameter value invalid | Check parameter constraints |
| **401** | `UNAUTHORIZED` | Missing or invalid auth | Provide valid authentication |
| **401** | `TOKEN_EXPIRED` | Auth token expired | Refresh token or re-authenticate |
| **403** | `FORBIDDEN` | Insufficient permissions | Contact admin for required role |
| **404** | `NOT_FOUND` | Resource not found | Verify resource ID exists |
| **409** | `CONFLICT` | Resource state conflict | Check current state before update |
| **422** | `PROCESSING_ERROR` | Business logic error | Review error details |
| **429** | `RATE_LIMITED` | Too many requests | Implement backoff/retry |
| **500** | `INTERNAL_ERROR` | Unexpected server error | Retry, contact support if persists |
| **502** | `UPSTREAM_ERROR` | Dependency service error | Check service health status |
| **503** | `SERVICE_UNAVAILABLE` | Service temporarily unavailable | Retry after delay |
| **504** | `GATEWAY_TIMEOUT` | Upstream timeout | Reduce request scope, retry |

### Domain-Specific Errors

| Error Code | Domain | Description |
|-----------|--------|-------------|
| `ALERT_NOT_FOUND` | Alerts | Alert ID does not exist |
| `ALERT_ALREADY_ACKNOWLEDGED` | Alerts | Alert already acknowledged |
| `INVALID_STATUS_TRANSITION` | Incidents | Not allowed status change |
| `CASE_CLOSED` | Incidents | Operation not allowed on closed case |
| `IOC_ALREADY_EXISTS` | Threats | Observable already in case |
| `ENRICHMENT_FAILED` | Enrichment | External service returned error |
| `QUOTA_EXCEEDED` | General | Resource quota limit reached |
| `DATA_MASKING_REQUIRED` | Telecom | Full value requires elevated access |

## Rate Limiting

### Rate Limit Headers

Every response includes rate limiting information:

```http
X-RateLimit-Limit: 1000
X-RateLimit-Remaining: 998
X-RateLimit-Reset: 1705320600
```

### Rate Limits by Endpoint Category

| Category | Requests/Window | Window |
|----------|-----------------|--------|
| **Public endpoints** (auth, health) | 60 | 1 minute |
| **Read operations** (GET) | 1000 | 1 minute |
| **Write operations** (POST, PATCH) | 200 | 1 minute |
| **Bulk operations** | 30 | 1 minute |
| **Real-time streams** (SSE) | 5 | 1 second |
| **Search/Analytics** | 60 | 1 minute |

### Handling Rate Limit Responses

When rate limited:

```json
{
  "success": false,
  "error": {
    "code": "RATE_LIMITED",
    "message": "Rate limit exceeded. Please retry after 60 seconds.",
    "details": {
      "retry_after_seconds": 60,
      "limit": 1000,
      "window": "1 minute"
    }
  }
}
```

**HTTP Headers on 429 Response:**

```http
HTTP/1.1 429 Too Many Requests
Content-Type: application/json
Retry-After: 60
X-RateLimit-Limit: 1000
X-RateLimit-Remaining: 0
X-RateLimit-Reset: 1705320600
```

### Python SDK Example

```python
from djezzy_soc import Client, Auth

# Initialize client
client = Client(
    base_url="https://api.soc.djezzy.local",
    api_version="v1"
)

# Authenticate
client.auth.login(
    username="analyst@djezzy.dz",
    password="secure_password"
)

# Fetch alerts
alerts = client.alerts.list(
    severity="critical",
    status="new",
    per_page=50
)

for alert in alerts:
    print(f"{alert.id}: {alert.title}")
    
    # Acknowledge if needed
    if alert.severity == "critical":
        alert.acknowledge(comment="Reviewing critical alert")

# Create incident
incident = client.incidents.create(
    title="Investigation from automated triage",
    severity="high",
    description="Auto-generated incident from alert correlation"
)

print(f"Created incident: {incident.id}")
```

### JavaScript/TypeScript SDK Example

```typescript
import { SocClient } from '@djezzy/soc-sdk';

const client = new SocClient({
  baseUrl: 'https://api.soc.djezzy.local',
  version: 'v1'
});

// Authenticate
await client.auth.login({
  username: 'analyst@djezzy.dz',
  password: 'secure_password'
});

// Subscribe to real-time alerts
const stream = client.streams.alerts();

stream.on('alert', (alert) => {
  console.log(`New ${alert.severity} alert: ${alert.title}`);
  
  if (alert.severity === 'critical') {
    // Auto-acknowledge critical alerts
    await client.alerts.acknowledge(alert.id, {
      comment: 'Auto-acknowledged by monitoring bot'
    });
  }
});

stream.on('error', (error) => {
  console.error('Stream error:', error);
});

// Start streaming
await stream.connect();
```

### cURL Examples Collection

```bash
#!/bin/bash
# soc_api_examples.sh - Common API usage examples

BASE_URL="https://api.soc.djezzy.local/api/v1"
TOKEN="your_jwt_token_here"

# ============================================================
# AUTHENTICATION
# ============================================================

echo "=== Login ==="
curl -s -X POST "$BASE_URL/auth/login" \
  -H "Content-Type: application/json" \
  -d '{"username":"analyst@djezzy.dz","password":"password"}' | jq .

# Save token for subsequent calls
TOKEN=$(curl -s -X POST "$BASE_URL/auth/login" \
  -H "Content-Type: application/json" \
  -d '{"username":"analyst@djezzy.dz","password":"password"}' | jq -r '.data.token')

# ============================================================
# ALERTS
# ============================================================

echo -e "\n=== List Critical New Alerts ==="
curl -s "$BASE_URL/alerts?severity=critical&status=new&per_page=5" \
  -H "Authorization: Bearer $TOKEN" | jq '.data[] | {id, title, severity}'

echo -e "\n=== Get Alert Details ==="
ALERT_ID=$(curl -s "$BASE_URL/alerts?severity=critical&status=new&per_page=1" \
  -H "Authorization: Bearer $TOKEN" | jq -r '.data[0].id')
  
curl -s "$BASE_URL/alerts/$ALERT_ID" \
  -H "Authorization: Bearer $TOKEN" | jq '.data | {id, title, iocs, status}'

echo -e "\n=== Acknowledge Alert ==="
curl -s -X POST "$BASE_URL/alerts/$ALERT_ID/acknowledge" \
  -H "Authorization: Bearer $TOKEN" \
  -H "Content-Type: application/json" \
  -d '{"comment":"Initial review","assign_to_self":true}' | jq .

# ============================================================
# INCIDENTS
# ============================================================

echo -e "\n=== List Open Critical Incidents ==="
curl -s "$BASE_URL/incidents?status=Open&severity=critical" \
  -H "Authorization: Bearer $TOKEN" | jq '.data[] | {id, title, status}'

echo -e "\n=== Create Incident ==="
curl -s -X POST "$BASE_URL/incidents" \
  -H "Authorization: Bearer $TOKEN" \
  -H "Content-Type: application/json" \
  -d '{
    "title": "Test Incident from API",
    "description": "Testing incident creation via API",
    "severity": 2,
    "tags": ["test", "api"]
  }' | jq '.data | {id, title, status}'

# ============================================================
# METRICS
# ============================================================

echo -e "\n=== Platform Health ==="
curl -s "$BASE_URL/metrics/health" \
  -H "Authorization: Bearer $TOKEN" | jq '.data.overall_status, .data.components'

echo -e "\n=== Alert Statistics (24h) ==="
curl -s "$BASE_URL/metrics/alerts/statistics?period=24h" \
  -H "Authorization: Bearer $TOKEN" | jq '.data.summary'

# ============================================================
# THREAT INTELLIGENCE
# ============================================================

echo -e "\n=== Search Threat Intel ==="
curl -s "$BASE_URL/threats/search?query=203.0.113.50&type=ip" \
  -H "Authorization: Bearer $TOKEN" | jq '.data.results[] | {source, type, value, threat_level}'

echo -e "\n=== Examples Complete ==="
```
